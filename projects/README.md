# 김소연 | PM 프로젝트 아카이브

> **문제를 구체화하고, 근거를 찾고, 팀이 실행할 수 있는 기획으로 연결합니다.**

## 프로젝트를 설명하는 방식

1. **WHY**: 어떤 사용자 문제와 운영 문제가 있었는가?
2. **EVIDENCE**: 정량 지표, 사용자 조사, 현업 상황에서 무엇을 확인했는가?
3. **MY ROLE**: 직접 기획하거나 관리한 범위는 어디까지인가?
4. **HOW**: 어떤 기능과 프로세스를 결정했고 팀과 어떻게 협업했는가?
5. **RESULT / NEXT STEP**: 확인된 성과와 아직 검증되지 않은 계획을 어떻게 구분하는가?

## 작업 범위와 자료

- 본 문서는 **김소연 PM 포트폴리오 PDF(33페이지)**와 공개적으로 확인되는 [ALLBLU 조직 소개](https://github.com/Project-ALLBLU/.github/blob/main/profile/README.md)를 바탕으로 작성한 GitHub용 정리입니다.
- **기획안, 검증 목표, 구현 완료, 운영 성과를 동일하게 취급하지 않습니다.** 검증 전 단계는 제안 또는 목표라고 표시했습니다.
- 팀 프로젝트는 개인의 개발 성과로 소개하지 않고, 포트폴리오에서 확인되는 **PM·기획 및 운영 기여 범위**를 중심으로 작성했습니다.
